# 버스 노선별 사용자수 예측 및 불편 신고접수 시스템 - 아이디어 정리

정리일: 2026-10-22 (개발 기간 약 2주 기준)

## 1. 핵심 범위 (확정)
- 노선별 사용자수 예측 (정답 데이터: 국토부 노선별 이용량_일별)
- 회원 전용 불편 신고 접수 (지도에서 정류장 선택, 최소 정보 가입: 이메일, 비밀번호, 닉네임)
- 관리자 대시보드: 이상 노선 목록, 수요 vs 공급(시간표), 예측 범위와 오차, 신고 연계

## 2. 후보 아이디어

| 아이디어 | 한 줄 설명 | 필요한 데이터 | 2주 난이도 | 상태 |
|---|---|---|---|---|
| **노선 유형 군집화** | 시간대 패턴이 비슷한 노선을 묶어 통근형, 통학형, 관광형 등으로 분류. 라벨 표시와 예측 입력 변수로 활용 | 이용량 일별 (시간대, 이용자 유형, 승/하차). 평일 2일 + 주말 2일, 약 180회 호출 | 낮음 | **후보** |
| 불편 지수 | 신고 건수를 이용량으로 나눠(이용자 1만 명당) 우선순위를 공정하게 계산 | 신고 DB + 이용량 | 낮음 | 후보 |
| 한산한 시간 추천 (시민용) | 노선, 시간대별 예상 혼잡을 시민에게 안내 | 예측 결과 | 중간 | 후보 |
| 날씨 연동 예측 | 비, 폭염, 한파가 노선과 시간대별 이용에 미치는 영향 | 이용량 + 기상청 API (미확인) | 낮음~중간 | 후보 |
| 이상일 탐지 | 평소와 크게 다른 날을 자동 표시, 공휴일·날씨 태그 | 이용량 + 공휴일 | 낮음 | 후보 |

| 교통약자 접근성 지도 | 경로, 장애인 이용 비율이 높은데 공급이 적은 지역 찾기 | 이용량(이용자 유형) + BIS 시간표 | 중간 | 후보 |
| 첫차, 막차 수요 | 새벽과 심야 이용 지역으로 첫차 앞당김, 막차 연장 근거 | 이용량 시간대 | 낮음 | 후보 |
| 철도(동해선) 연계 | 철도 이용이 많은 읍면동의 버스 연계 수요 | 이용량 (철도 코드 T) | 중간 | 후보 |
| 구간별 혼잡 색 지도 | 노선 구간별 혼잡을 색으로 표시, 클릭 시 예측 | 노선별 혼잡도 / 차내 재차인원 (API 호출 미확인) | 높음 | 후보 (데이터 확인 필요) |
| 전면 개편 전후 비교 | 2024-12-21 개편 전후를 같은 계절(2024 가을 대 2025 가을)로 비교. 지역, 시간대, 이용자 유형별 변화 | 이용량 일별 (수집 완료 12개 일자 포함) | 중간 | 후보 (진행 여부 확인 중) |

## 3. 보류
- **중간 개편(미세조정) 반사실 비교**: 조정 규모가 승차의 1% 안팎이고 노선 ID가 재부여돼 노선 추적이 어려움. 기점, 종점 이름으로 노선을 다시 매칭해 본 뒤 결정.

## 4. 제외
- **수익성 계산**: 운행 비용과 실제 수입 데이터가 없음 (2026-10-22 팀 결정).
- 울산광역시 교통정보 API: 폐지된 서비스.

## 5. 데이터 메모
- 이용량 API: `https://apis.data.go.kr/1613000/TripVolumebyRoute/getDailyTripVolumebyRoute` (numOfRows 최대 1000, 기간 2024-09-01 ~ 2026-09-25, 일 한도 1,000건)
- BIS GW: `https://apis.data.go.kr/6310000/bis` (오퍼레이션 6개, 일 한도 오퍼레이션별 1,000건, XML만 제공)
- 노선 ID는 개편 이후에도 재부여되므로 노선 식별은 `rte_id` + 기점 + 종점 이름으로 하고, 예측 단위는 읍면동 또는 노선 군집이 더 안정적.
- 이용량 데이터는 과거 값만 있어 "내일 같은 시간대" 예측으로 해석.
